# GLaDOS Quick Deploy 1.2.0

本版是在 1.1.2 基础上的功能升级。程序名称、App ID 和既有数据目录保持不变。三个交付平台为 Windows x64、macOS Apple Silicon、macOS Intel。云端运行无需电脑保持开机。

## 从 1.1.2 升级

先完全退出旧版，将新版 `GLaDOS Quick Deploy.app` 拖到原安装位置，选择替换。只替换 `.app`，不要替换或删除外层 `GLaDOSQuickDeploy` 文件夹，也不要删除 `Data`。Windows 使用新版安装程序覆盖原安装目录。

已有账号、备注、已保存任务和设置自动读取；旧单时间设置转换为时间列表，原先的 12:30 不会被重置为 09:30。MacData 用户的数据目录仍是 `/Volumes/MacData/Applications/GLaDOSQuickDeploy/Data`。没有 MacData 时使用系统用户数据目录；记录过原数据位置后，如果原磁盘不可用，程序会停止并说明情况，不悄悄新建一个空账号库。

首次打开新版后点击 **一键升级全部云端配置**。此按钮根据云端当前账号清单逐仓库更新所有账号，而不是只更新当前选中的账号。已存在的登录 Secrets 不会重新上传，账号无需逐个重新登录。成功写入后读回验证，重复点击已完成的升级不会重复改写文件；并行配置变化会停止覆盖并提示刷新。暂停的部署不会被静默重新开启。

新版增加了加密账号报告。第一次建立或解密报告密钥时，macOS 可能要求系统钥匙串授权。请输入系统钥匙串密码，不是 GLaDOS 密码。密码无法接受时不要重置整个钥匙串。普通启动及后台只读状态读取不会为了空恢复文件主动初始化钥匙串。迁移到其他电脑或另一个系统用户，不保证原系统加密密钥可解密，不能当作同机覆盖升级。

## 账号与云端管理面板

新版主面板提供：一键升级全部云端配置、一键全部账号签到、全部账号信息查询、刷新已有结果、读取加密详情、批量编辑所选账号。每张账号卡片还提供编辑设置、查询信息、签到、更新登录、查看运行记录与本机备注。

**一键全部账号签到**会对所有管理仓库中的启用账号提交签到任务。账号仍逐个执行，不是并发请求；已暂停的账号跳过。按钮忙碌时禁用；网络响应不确定时记录请求标识，重新打开应用或继续任务会查找原请求，不盲目重复发送。应用退出不会取消已经交给 GitHub 的云端任务。

**查询信息**是只读查询 GLaDOS 的状态和积分，不发起签到或兑换。**刷新已有结果**只读取 GitHub 中已经存在的运行记录，不新建 GLaDOS 请求。两者与签到按钮明确分开。

## 多个定时触发时间与补漏

每个账号可以设置 1–6 个 `HH:mm` 时间，用逗号分隔，例如 `12:30, 18:37, 22:13`。时间固定按台湾时间／北京时间 UTC+8。相同时间自动去重；不同账号可以使用不同时间和兑换方案。单仓库最多 100 个账号、100 个不同定时时点。

云端工作流在同一时点只选择对应账号，并串行处理。前一个时点未运行或明确的临时失败，后一个时点仍可处理；已有当日成功证据的账号不重复签到。需要登录的授权拒绝不反复尝试；更新登录后恢复。请求是否已被服务端执行无法确定时，程序标记待核实而不是假设失败后反复提交。每日按 UTC+8 的日历日期区分，不用最近 24 小时冒充今日。

多个 cron 仍依赖 GitHub 的同一调度平台，不是两个独立服务。GitHub 全局故障、仓库停用、登录过期不会因为增加时间而自动消失。页面将“配置已保存”“主动触发成功”“真正定时触发已经观察到”分开。只有运行事件为 `schedule` 才作为定时触发证据；预定时间不保证精确到秒。

## 部署后修改设置

在账号卡片选择“编辑设置”，或者勾选多个账号后批量编辑。可修改多个签到时间、兑换档位和启用／暂停状态。保存时只更新选中账号，并使用云端配置指纹避免覆盖其他电脑的并行编辑；写入后读回一致才报告生效。修改设置本身不额外签到，也不要求重新登录 GLaDOS。

兑换选项：关闭自动兑换、100 分换 10 天、200 分换 30 天、500 分换 100 天。只有已确认签到或当日已签到时才进入兑换判断，查询不到积分时不兑换；兑换结果不确定时不重复扣分。签到和兑换结果分开记录，兑换失败不会抹掉已有签到成功。实际套餐可用性和兑换接口结果以 GLaDOS 返回为准。

## 今日状态与账号信息

账号面板显示今日签到状态、全部触发时间、下一个计划时间、最近实际执行、当前积分、当日观测新增积分、剩余会员天数、兑换方案与结果。接口没有返回的值显示“未获取”，不伪造为 0。每份信息显示采集时间；昨天成功不标成今天成功，离线历史不冒充实时信息。

邮箱与余额等详情在云端使用 RSA-OAEP-SHA256 + AES-256-GCM 加密；私钥由本机系统安全存储保护。公开运行日志和匿名回执不包含 Cookie、User-Agent、完整邮箱或余额详情。第一次读取加密详情需系统授权，此后同次打开期间可用已解锁的内存密钥刷新。GitHub 授权继续使用官方 GitHub CLI 登录。

## 独立的三天清理与保活

`GLaDOS Quick Deploy Cleanup` 是单独的每日工作流，默认 UTC+8 03:43。它删除本部署已完成且最后创建／运行／更新都早于 72 小时前的运行；近期重跑、排队、执行中、当前清理任务不会被删除。删除前再次核对状态，完整处理分页，失败不记为已删除。只处理 Quick Deploy 的签到、状态查询、清理及保活任务，不操作其他工作流、账号 Secrets 或源码。

附件上传时明确 `retention-days: 3`，仓库原生保留期也设为 3 天并读回验证。依赖缓存另按本项目缓存名前缀和最后使用时间清理，近期缓存保留。每日清理不是秒级过期，两次清理间可能暂存超过 72 小时的记录。此措施控制本部署空间，不保证其他仓库或账户级 Packages 的空间一定足够。

App 中“维护设置”可修改清理时间、清理启用状态与保活开关。“立即清理过期记录”运行同一套保护规则，不是清空仓库。面板显示最近清理结果和可核实的删除数量。

`GLaDOS Quick Deploy Keepalive` 默认每月 1 日 UTC+8 11:23 提交一个活动时间戳，减少公开仓库长期没有活动后定时器被平台停用的风险。它不是签到、补签、刷新 Cookie 或维持账号登录。尚未到第一次保活时点时显示“尚未运行”，不是空实现。

## 签名与使用边界

Mac 安装包使用 ad-hoc 签名，尚未 Apple 公证；Windows 尚未商业代码签名。系统可能提示来源确认。使用成品校验值确认文件来源，不全局关闭系统安全功能。新版替换后仍可能需要系统重新授权访问特定钥匙串项。

GLaDOS 邮箱验证码、网站验证和 GitHub 首次授权仍由用户本人完成。本应用不绕过网站验证，不自动获取邮箱验证码，不保持后台浏览器抢占焦点。Safari 不提供 GLaDOS 自动会话采集，使用已支持浏览器或内置登录窗口。

## 验收口径

构建与本地单元测试不等于真实账号验收；以交付随附 `BUILD-VERIFICATION.json` 中的平台原生检查和实际云端运行记录为准。真正定时触发尚未观察到时必须显示未验证，不能把手动触发或测试夹具的成功记为定时签到成功。

旧版程序仅在原位替换期间暂存以便失败回退；安装验证完成后删除旧程序副本和任务临时文件。保留维护源码、正式安装包与精简验证记录，不长期堆放多套已安装 App。
