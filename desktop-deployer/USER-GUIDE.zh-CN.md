# GLaDOS Quick Deploy 中文使用指南

**适用版本：1.1.2**

首次使用时，选择登录浏览器后点击“一键部署”。已有未完成任务时，选择“继续未完成任务”；要加入另一账号，使用账号列表中的“添加账号”。需要时，你只负责在 GitHub 官方页面完成授权、在 GLaDOS 官方页面完成登录；仓库创建、登录信息配置、计划任务与首次运行验证由软件接续处理。

**1.1.2 启动修复：** 没有本地加密恢复文件时，启动恢复模块不再调用系统安全存储，避免无待恢复会话却出现 Safe Storage 钥匙串提示。实际保存或恢复加密会话时，仍使用系统保护。

**1.1.1 结果修复继续保留：** GitHub 已完成运行、账号却因日志读取中断而反复显示“结果待核实”的问题已修复；取得账号结果后，顶部验证进度和账号卡片同步更新。明确签到成功但新增积分为 0 时，会显示“签到成功”。升级后，直接刷新原账号即可重新读取已有结果，无需重复添加账号或重新部署。

此前 1.1.0 已修复 GitHub 工作流权限误报，并提供错误处理按钮、任务断点恢复及独立的账号添加和更新入口，这些功能继续保留。真正缺少权限、网络故障或网站拒绝登录时，仍需按具体提示处理。

**从 1.0.0 升级：** 原有账号记录与设置保留。旧版已经清掉的失败登录会话无法事后找回，升级后首次可能需要重新登录一次；此后 1.1.0 会按已保存的检查点接续允许恢复的步骤。新版原生安装包和设备检查请核对对应版本的产物记录，不能把旧版构建结果视为新版已经验收。

## 1. 选择并安装对应版本

| 你的电脑 | 使用的安装包 |
| --- | --- |
| Windows 10 / 11，Intel / AMD 64 位电脑 | Windows x64 的 `.exe` 安装包。 |
| 配备 Apple Silicon、运行 macOS 13 或更新系统的 Mac | macOS ARM64 的 `.dmg` 或 `.zip`。 |
| 配备 Intel 处理器、运行 macOS 13 或更新系统的 Mac | macOS x64 的 `.dmg` 或 `.zip`。 |

Mac 最低要求为 **macOS 13 Ventura**；macOS 12 或更早系统不在本版本支持范围内。

Windows 打开安装程序，按向导选择安装目录。Mac 打开 DMG 后把应用放入自己的应用目录；使用 ZIP 时，解压后移动 `.app` 再打开。使用 MacData 的 Mac 可以将应用放在 `/Volumes/MacData/Applications` 下，保持外置安装习惯。

升级时覆盖原位置的应用并保留数据目录；新版验证通过后，清理旧应用副本和安装临时文件，避免保留多个版本。

安装包已包含应用所需组件，不需要另外安装开发工具或 GitHub CLI。

**签名说明：** Windows 版本尚未使用微软代码签名证书；Mac 版本使用 ad-hoc 签名，未完成 Apple 开发者公证。系统可能显示来源确认提示。先确认包来自本次交付或可信源码构建，并核对随包校验值，再按系统提供的正常提示处理。如系统不允许正常打开，应先核查原因，不要关闭系统安全保护。

使用 GitHub 授权或本机加密恢复功能时，系统可能请求正常的钥匙串或凭据服务访问。核对请求的应用后，按系统提示处理；拒绝或暂时无法访问时，软件会显示相应提示。

## 2. 保持默认设置即可开始

| 设置 | 默认值与作用 |
| --- | --- |
| 登录浏览器 | 优先使用识别到的 Brave；也可以选择“应用内登录窗口”。 |
| GitHub 仓库名称 | `glados-quick-deploy`。软件自动创建或更新自己的专用部署仓库。 |
| 每日运行时间 | **09:30，UTC+8**，即北京时间 / 台北时间。GitHub 排队可能使实际运行延后。 |
| 积分兑换 | **500 积分换 100 天**。也可改为 200 积分换 30 天、100 积分换 10 天，或关闭自动兑换。 |

达到所选计划的条件后，任务会尝试兑换，是否成功以服务端结果为准。

仓库名称为 1–80 个字符，以英文字母或数字开头，可包含点、横线和下划线。同一仓库的全部账号共用设置中的运行时间和兑换计划；再次部署时修改这些设置，会对该仓库生效。

## 3. 点击“一键部署”并完成登录

**GitHub 授权。** 如果电脑上的官方 GitHub CLI 已有可用身份，软件会复用它。需要登录或补充权限时，应用显示设备授权码，并打开 GitHub 官方授权页面。按照网页提示登录、输入显示的授权码并确认页面列出的授权。完成后应用自动继续，不需要手动创建令牌。界面右上角显示实际使用的 GitHub 账号；需要重新授权时使用该按钮。

若错误卡提示补充 GitHub 授权，直接使用卡片内的“补充 GitHub 授权并继续”。继续原任务时应使用该任务绑定的原 GitHub 账号，软件会核对账号及仓库身份。

**GLaDOS 登录。** 软件打开专用登录窗口，在里面使用你希望部署的 GLaDOS 账号登录。邮箱验证码以及官网要求的其他验证都由你在官网完成。不要把密码、验证码或 Cookie 发给他人，也不需要把它们复制进应用设置。

**自动部署与验证。** 登录身份确认后，程序自动配置仓库和该账号的登录信息，启动首次验证并显示进度。如果同一仓库已有任务在运行，程序会等待后接续，避免同时提交多组账号操作。

点击“取消任务”可以停止当前本机操作，已经保存的未完成任务可稍后继续。已经提交到 GitHub 的运行可能继续，取消本机等待不会自动撤回它。

**出错或重启后继续。** 在“未完成任务”中选择原任务，再点击旁边的继续按钮，或使用错误卡中的对应处理按钮。程序沿用该任务保存的账号、仓库和设置，不读取“添加账号”表单的新设置。已确认上传的登录信息、已提交的配置和已有运行记录会按远端状态核对后接续；只有会话确实需要补充时才重新打开登录窗口。

如果显示“继续查询原任务”或验证请求待确认，点击继续只会查询原请求。软件不会自动再提交一次签到；尚未找到运行记录时也不会显示成功。网络恢复后仍无法确认的请求，应保留待办并查看 GitHub 运行记录。

## 4. 看懂结果再判断是否成功

| 界面结果 | 应如何理解 |
| --- | --- |
| 已加分 +N | 本次有可核实的积分增加。 |
| 今日已签到 | 服务端结果表明该账号今天已经签过到。 |
| 签到成功 | 有对应账号的签到接受结果；新增积分为 0 也可以是有效的签到成功，不会被误算为“已加分”。 |
| 工作流成功 | GitHub 工作流运行成功；仅凭这项不能判断一定加分，应查看账号提示和运行记录。 |
| 结果待核实 | 已有运行记录，但尚未取得该账号完整的签到结果；查看卡片中的具体读取原因，刷新或打开原运行记录进一步核实。 |
| 验证排队 / 正在验证 | 尚未取得最终结果。等待自动更新或使用账号卡片的刷新按钮。 |
| 运行异常，同时显示已加分 | 已经取得积分，但兑换或其他运行步骤有问题，仍需查看具体记录。 |
| 需要重新登录 / 授权被拒绝 | 当前会话没有被网站接受，按下节重新登录更新。 |

顶部第 4 步与当前账号的验证结果同步；缺少可核实的账号结果时，不会仅因工作流成功而把验证标成完成。完成验证也不代表一定新增积分，应同时查看账号卡片。软件的构建检查与窗口检查不能证明你的账号已签到。

**本版本尚未通过真实账号的完整端到端登录、部署、签到及兑换验收。** 首次使用时，账号卡片和 GitHub 上本次运行的实际结果才是验收依据。GLaDOS 后续可能调整认证或自动化检测，本软件不保证所有账号和未来版本长期免维护。

## 5. 添加账号、更新会话与暂停

**添加账号：** 点击账号列表中的“添加账号”，设置新账号的登录方式，再开始部署。在专用窗口登录另一个 GLaDOS 账号。使用同一仓库名称即可加入同一套任务；不同账号的登录信息分别保存。已有待办会保留，“添加账号”不会代替“继续原任务”。

**更新原账号的登录信息：** 在对应账号卡片点击“更新登录”，使用原 GitHub 账号，在 GLaDOS 窗口登录这张卡片对应的原账号。程序核验身份后更新对应记录，无需手动编辑 Secrets。网站明确要求重新登录时，重复刷新旧会话不会代替新的官方登录。若该账号还有待确认的验证请求，应先继续查询原任务。

**查看运行：** 使用“刷新全部”读取已部署账号的运行结果，或在账号卡片逐个刷新、打开 GitHub 运行记录和所属仓库。刷新读取已有结果，不额外提交签到。未完成部署的账号应先继续对应待办。如果结果异常，先看这一账号的具体说明，避免把一般网络错误和登录拒绝混为一谈。

**数量与顺序：** 同一仓库最多 100 个账号。桌面端每次处理一个账号的登录与部署，完成或取消当前操作后再处理下一个；定时签到也按串行方式执行。

**暂停 / 恢复：** 暂停操作作用于**此仓库全部账号**，不是只暂停当前这一张账号卡片。恢复也对同一仓库一起生效。需要分别设定时间、兑换计划或独立暂停的账号，应使用不同仓库。

部署完成后可以退出应用、关闭电脑，已建立的 GitHub Actions 仍按计划运行。想停止云端定时签到，请先暂停对应仓库；仅退出应用或卸载应用不会删除 GitHub 上的任务。

## 6. 浏览器如何选择

应用会检查 Brave、Chrome、Edge、Firefox、Opera、Vivaldi、Chromium，以及 macOS 上的 Arc 的常见安装位置。不同浏览器版本、安装位置和连接协议会影响可用性；本版本没有对所有品牌、版本和电脑逐一完成真实登录测试。

优先使用应用已识别到的 Brave 或其他 Chromium 系浏览器。外部浏览器连接失败、安装位置未被识别，或不想使用外部浏览器时，可以选择**应用内登录窗口**，无需安装浏览器扩展。

Safari 可作为 GitHub 网页授权使用的浏览器，但本版本不通过 Safari 自动取得 GLaDOS 登录会话。Mac 上的 GLaDOS 登录请选其他已识别浏览器，或应用内窗口。

软件为 GLaDOS 打开独立的专用登录会话，不使用日常浏览器的个人 profile。完成登录或取消后会关闭本次专用窗口，这不会清空你日常浏览器的账号。

## 7. 数据放在哪里，哪些内容会公开

软件会在你的 GitHub 中自动建立专用的**公开部署仓库**。公开部分包含任务配置、上游版本与不含邮箱的账号 ID，不包含账号 Cookie。每个账号的会话分别保存在 GitHub Actions Secrets 中，不需要你手动粘贴。

本机保存应用设置、账号邮箱、仓库与运行结果，方便下次打开后查看。1.1.0 的恢复数据分为两部分：

| 本机文件 | 保存内容与用途 |
| --- | --- |
| `deployment-state.json` | 设置、账号记录及不含 Cookie、令牌的任务检查点。保存已经确认的部署阶段、原仓库身份、验证请求标识和运行编号，供重启后续做。 |
| `pending-deployments.enc` | 尚未确认上传至 GitHub Secret 的登录会话，由主进程调用系统 `safeStorage` 加密保存，不会以明文 Cookie 落盘。 |

待上传会话的默认保存期限为 **7 天**，按任务最近更新时间计算；软件在读取或保存恢复记录时移除过期登录信息。这个期限不代表 GLaDOS 保证会话有效 7 天，官网可能提前要求重新登录。确认 Secret 上传成功后，软件从本地待办移除该凭据并更新加密记录，后续配置与运行查询可使用已保存的非秘密进度。

系统安全存储不可用时，软件不会改用明文保存 Cookie：尚未上传的会话只保留在本次运行的内存中，非秘密进度仍会保存，重启后必要时需要重新登录。磁盘空间、目录权限或钥匙串异常可能影响保存或清理，界面会给出提示；应先处理对应问题，不能把存储异常理解为已成功保存全部数据。

外部浏览器登录期间使用应用管理的临时目录，正常结束时清理。如果目录暂时被系统占用，应用会在后续启动时重试清理。内置登录窗口使用独立的非持久化会话。

GitHub 身份由官方 `gh` 的标准会话机制管理，软件会复用已有登录，不退出或清空原有会话。官方 `gh` 的凭据存储与 GLaDOS 临时登录数据不同，不应把本软件理解为“所有授权信息只存在于内存”。

应用底部的“本机数据位置”显示实际数据目录。Mac 检测到可写的 MacData 时，优先使用 `/Volumes/MacData/Applications/GLaDOSQuickDeploy/Data`；其他电脑使用系统应用数据位置。

“移除本地待办”只移除所选恢复任务，不会删除 GitHub 仓库、已上传 Secret 或已提交的运行。需要停止每日云端签到时，应使用仓库暂停操作。

## 8. 遇到问题时按对应入口处理

| 提示或情况 | 应如何处理 |
| --- | --- |
| 旧版反复要求工作流权限 | 升级后重试。1.1.0 已修复正常权限响应头造成的误报；若确实缺权，使用错误卡的补权按钮，完成原 GitHub 账号授权。 |
| 网络中断、限流、GitHub 暂不可用 | 恢复网络或等待限制解除，然后继续原任务。已经保存的步骤可复用，不必主动添加一个重复账号。 |
| 重开后提示“登录并继续” | 原进度仍在，但登录会话未能保留、已过期，或来自无法恢复会话的 1.0.0 失败任务。重新登录对应账号后继续。 |
| 网站拒绝会话 | 在对应账号卡片选择“更新登录”，完成官网要求的验证；不能靠刷新保证旧会话恢复。 |
| GitHub 账号或仓库身份不符 | 连接原任务绑定的 GitHub 账号，核对仓库；软件不会将原账号会话上传到另一身份的仓库。 |
| 远端配置发生变化 | 核对 GitHub 仓库与本任务保存的设置。普通继续只会重新核对；若要主动重新应用原设置，使用错误卡的“更新登录并重新部署”。同一仓库的时间和兑换计划会对全部账号生效。 |
| 添加时登录了已有待办的账号 | 同一仓库会接回原任务并保留原设置；如果原待办属于其他仓库，先选择继续原任务，或移除原本地待办后再添加。 |
| 验证请求待确认 | 继续查询原请求或查看 GitHub 运行记录。未确认不等于签到成功，软件也不会自动重复提交。 |
| GitHub 已结束，账号反复待核实 | 1.1.1 已修复日志颜色控制符造成的读取中断。刷新原账号即可重新读取，不需要重新部署；仍待核实时按卡片显示的具体原因处理。 |
| 本机安全存储或写入失败 | 按提示检查正常的系统凭据访问、磁盘空间与目录权限；会话无法跨重启保留时，需要再次登录。 |
